# Onboarding Paywall Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show the Glutt Superwall paywall right after the onboarding import tutorial, with skip dropping the user into the full, unlocked app.

**Architecture:** Add the SuperwallKit SDK, configure it at app launch, and replace the existing no-op `OnboardingPaywallHook` with a `Superwall.shared.register(placement:)` call. A non-gated Superwall campaign on the `onboarding_complete` placement presents the paywall; closing it fires the feature block which completes onboarding. No feature gating is added anywhere.

**Tech Stack:** SwiftUI, SwiftData, SuperwallKit (SPM), XcodeGen.

## Global Constraints

- iOS deployment target **17.0**; Swift **5.10**; SwiftUI + SwiftData (no UIKit views).
- Project is generated by **XcodeGen** from `project.yml` — after editing `project.yml`, regenerate with `xcodegen generate`. Never hand-edit `Glutt.xcodeproj`.
- SuperwallKit: `https://github.com/superwall/Superwall-iOS`, latest stable **4.x** (`from: "4.0.0"`). App target **only** (not GluttShare or GluttTests).
- Placement name is exactly **`onboarding_complete`** (must match the Superwall campaign).
- Paywall is **non-gated**: skip = the paywall's ✕ close button → fail-open → main app. **No feature gating** anywhere.
- Superwall public (publishable) API key `pk_…` — safe to embed. References: app id `47883`, paywall id `234287`, products `com.glutt.premium.yearly` ($39.99/yr), `com.glutt.premium.monthly` ($7.99/mo).
- This is SDK wiring with no pure business logic, so tasks are verified by **successful build + manual run-through**, not unit tests. That is intentional (YAGNI), not an omission.

### Task 2: Wire the onboarding hook to the Superwall placement

**Files:**
- Modify: `Glutt/Features/Onboarding/Support/OnboardingPaywallHook.swift:1-16`

**Interfaces:**
- Consumes: a configured `Superwall.shared` (from Task 1).
- Produces: `OnboardingPaywallHook.presentPostOnboarding(completion:)` now registers the `onboarding_complete` placement and calls `completion` from the feature block. (Already consumed by `OnboardingFlow.finish(thenImport:)`; no caller change needed.)

- [ ] **Step 1: Replace the file contents**

Replace the entire contents of `OnboardingPaywallHook.swift` with:

```swift
import SuperwallKit

/// Single integration point for the post-onboarding paywall.
///
/// Registers the `onboarding_complete` placement. Superwall presents the paywall
/// configured for that placement in the dashboard; `completion` runs from the
/// feature block — after the user dismisses/skips the paywall, immediately if the
/// user is already subscribed, or immediately if no paywall can be shown
/// (no network / no matching campaign). That "fail-open" behavior guarantees
/// onboarding always finishes.
///
/// Keeping it isolated means onboarding code never changes when the paywall changes.
enum OnboardingPaywallHook {
    static func presentPostOnboarding(completion: @escaping () -> Void) {
        Superwall.shared.register(placement: "onboarding_complete") {
            completion()
        }
    }
}
```

- [ ] **Step 2: Build to verify it compiles**

Run:
```bash
xcodebuild -project Glutt.xcodeproj -scheme Glutt \
  -destination 'platform=iOS Simulator,name=iPhone 16' \
  -configuration Debug build
```
Expected: `** BUILD SUCCEEDED **`.

- [ ] **Step 3: Commit**

